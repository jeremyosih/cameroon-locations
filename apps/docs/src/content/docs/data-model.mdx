## Administrative units

Regions, divisions and arrondissements share one shape and differ by `level`
and their parent links. `AdminUnit` is the union of the three; switch on
`level` to narrow it.

```ts
type AdminLevel = "region" | "division" | "arrondissement";
type AdminUnit = Region | Division | Arrondissement;
```

Parent links by level:

| Type             | `parentPcode` | Also                              |
| :--------------- | :------------ | :-------------------------------- |
| `Region`         | `null`        |                                   |
| `Division`       | region        | `regionPcode`                     |
| `Arrondissement` | division      | `regionPcode`, `divisionPcode`, `ordinal?` |

`ordinal` is set on numbered arrondissements: `1` for "Yaoundé I", `3` for
"Douala III".

```ts
import type { AdminUnit } from "cameroon-locations";

function label(unit: AdminUnit): string {
  switch (unit.level) {
    case "region":
      return unit.name.en;
    case "division":
      return `${unit.name.fr} (${unit.regionPcode})`;
    case "arrondissement":
      return `${unit.name.fr}, ${unit.divisionPcode}`;
  }
}
```

## Cantons and villages

Cantons and villages come from the BUCREP census directory. Their `name` is
kept exactly as printed (upper case); `label` is a friendlier casing for
display.

## Conventions

- **Frozen.** Records and arrays are deep-frozen. Copy before you change
  anything: `{ ...unit }`.
- **Serialisable.** No classes, dates or functions; `JSON.stringify` round-trips.
- **Coordinates** are `[lng, lat]`, like GeoJSON. Leaflet wants `[lat, lng]`.
- **Missing values** are omitted (`?`), never `null`, except
  `Region.parentPcode` and diaspora polling stations.
- **Population** figures are the 2005 census, as printed by BUCREP, even where
  the source's own totals disagree. Known inconsistencies are listed in
  `data/canonical/issues.json`.
