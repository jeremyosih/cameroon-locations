## Installation

<InstallCommand client:load shadcn={registryUrl("location-picker")} />

This adds `components/location-picker.tsx`, the shadcn/ui `popover`,
`command` and `button` primitives, and the
[`cameroon-locations-core`](/docs/installation#copy-and-paste-with-shadcn) item in
`lib/cameroon-locations/`: the types, lookups and search with the 428
regions, divisions and arrondissements inlined. There is no npm dependency.

<Callout title="Radix or Base UI">
  The picker works in projects on either flavour of shadcn/ui (`shadcn init
  -b radix` or `-b base`). The CLI installs the `popover`, `command` and
  `button` that match your project, and the picker only uses what both
  versions share.
</Callout>

## Usage

```tsx
import { LocationPicker } from "@/components/location-picker";

<LocationPicker
  defaultValue="CM002007001"
  onValueChange={(selection) => console.log(selection.pcode)}
/>;
```

Each level is a combobox. Open it and type: search is accent-insensitive
and typo-tolerant, and matches French and English names and aliases, so
"extreme nord", "far north" and "Extrême-Nord" all find the region. When the
match is an alias or the other language, it is shown next to the name.

Choosing a parent clears the levels below it, and the next combobox gets
focus. Choosing the selected entry again clears it.

### Values

The value is a P-code, so what you store is the stable OCHA code and the
names come from the data in either language. Pass the code of any level:
parents are derived from it.

```tsx
<LocationPicker value="CM002007001" />  {/* Centre › Mfoundi › Yaoundé I */}
<LocationPicker value="CM002" />        {/* Centre, nothing below */}
<LocationPicker value={{ division: "CM002007" }} />
```

`onValueChange` receives the records, not only the codes:

```ts
interface LocationSelection {
  region: Region | undefined;
  division: Division | undefined;
  arrondissement: Arrondissement | undefined;
  unit: AdminUnit | undefined; // the deepest selected unit
  pcode: Pcode | undefined; // its P-code
}
```

It works uncontrolled (`defaultValue`) or controlled (`value` with
`onValueChange`; `null` clears it).

### Depth and language

```tsx
<LocationPicker depth="division" lang="fr" />
```

`depth` stops at the region or division. `lang` switches the names and the
default labels ("Région", "Département", "Arrondissement"). Override any
text with `labels`, `placeholders`, `searchPlaceholder` and `emptyMessage`.

## Examples

### In a form

With `name`, the picker renders a hidden input holding the deepest selected
P-code, so it submits with the form like any field. Here it is controlled,
in French, and the submit button waits for an arrondissement.

## Accessibility

- Every trigger has a visible `<label>` and is a `combobox` button with
  `aria-expanded`; the popover list is a listbox from
  [cmdk](https://cmdk.paco.me).
- Keyboard: Tab to a level, Enter or Space opens it, type to search, arrow
  keys move, Enter chooses, Escape closes. After a choice, focus moves to the
  next level.
- Names follow `lang`; the search accepts both languages either way.
