Effect v4 schemas that turn untrusted input into the records the core
returns. `effect` 4 is an optional peer dependency: only this entry point
imports it, and like `effect` 4 it is ESM-only.

<InstallCommand client:load packages="cameroon-locations effect" />

```ts
import { Result, Schema } from "effect";
import { ArrondissementFromString } from "cameroon-locations/effect";

const Signup = Schema.Struct({
  email: Schema.String,
  commune: ArrondissementFromString, // a P-code, HASC code or name
});

export async function POST(request: Request): Promise<Response> {
  const result = Schema.decodeUnknownResult(Signup)(await request.json());
  if (Result.isFailure(result)) {
    return Response.json({ error: result.failure.message }, { status: 400 });
  }
  const { email, commune } = result.success; // commune: Arrondissement
  return Response.json({ email, commune: commune.pcode, region: commune.regionPcode });
}
```

`{ "email": "a@b.cm", "commune": "Yaoundé 1er" }` gets a 200 with
`"commune": "CM002007001"` and `"region": "CM002"`; `"commune": "nowhere"`
gets a 400 with `No arrondissement matches "nowhere"` at `["commune"]`.

For plain lookups, use the core: `getRegion(q)` returns `Region | undefined`,
and `Option.fromUndefinedOr(getRegion(q))` makes it an `Option`.

## Decoding input

Each decoder takes a string and decodes it into the bundled record: the
same frozen object the core returns. It encodes the record back to its
P-code, so you can store or send the code.

| Schema | Accepts |
| :----- | :------ |
| `RegionFromString`, `DivisionFromString`, `ArrondissementFromString` | A P-code, HASC code or name, as in the core [lookups](/docs/lookups#queries) (case, accents and numbering style ignored) |
| `RegionFromPcode`, `DivisionFromPcode`, `ArrondissementFromPcode` | That level's P-code only: for `<select>` values, route params and stored ids |
| `AdminUnitFromPcode` | A P-code of any level |

```ts
import { Schema } from "effect";
import {
  AdminUnitFromPcode,
  ArrondissementFromPcode,
  ArrondissementFromString,
  RegionFromString,
} from "cameroon-locations/effect";

Schema.decodeUnknownSync(RegionFromString)("littoral").pcode; // "CM005"
Schema.decodeUnknownSync(ArrondissementFromString)("Yaounde 1").pcode; // "CM002007001"
Schema.decodeUnknownSync(AdminUnitFromPcode)("CM002007").level; // "division"

const Form = Schema.Struct({ commune: ArrondissementFromPcode });
const { commune } = Schema.decodeUnknownSync(Form)({ commune: "CM002007001" });
Schema.encodeSync(Form)({ commune }); // { commune: "CM002007001" }
```

Failures are ordinary schema issues, at the path of the field:

| Input | Message |
| :---- | :------ |
| Unknown name or code (`*FromString`) | `No arrondissement matches "nowhere"` |
| Name shared by several units (`*FromString`) | `"…" matches 2 arrondissements: CM…, CM…`. No name is shared in the current data, but aliases may collide as sources are added |
| Unknown P-code (`*FromPcode`) | `Unknown arrondissement P-code "CM002007999"` |
| Malformed P-code (`*FromPcode`) | `Expected an arrondissement P-code such as CM002007001` |

In an Effect, they arrive as a `SchemaError` in the error channel:

```ts
import { Effect, Schema } from "effect";
import { RegionFromString } from "cameroon-locations/effect";

const program = Schema.decodeUnknownEffect(RegionFromString)("Atlantis").pipe(
  Effect.map((region) => region.name.fr),
  Effect.catchTag("SchemaError", (error) => Effect.succeed(error.message)),
);
Effect.runSync(program); // 'No region matches "Atlantis"'
```

## Record schemas

Every type of the [data model](/docs/data-model) has a schema, for records
that left the process and came back (a cache, a queue, another service).
They check the shape and that a record's codes agree with each other (a
division's `parentPcode` and `regionPcode` start its `pcode`, a village's
`id` starts with its `cantonId`, and so on), not that the unit exists: use
the decoders above for that. Their types are checked against the core types
at build time.

| Schema | Validates |
| :----- | :-------- |
| `Pcode` | Any P-code: `CM001`, `CM001001` or `CM001001001` |
| `RegionPcode`, `DivisionPcode`, `ArrondissementPcode` | A P-code of one level |
| `CantonId`, `VillageId` | `CM002007001-C01`, `CM002007001-C01-V001` |
| `AdminLevel`, `Language`, `SourceId` | The literal unions |
| `LocalizedName`, `Alias`, `Population`, `LngLat`, `BBox` | Building blocks |
| `Region`, `Division`, `Arrondissement` | Administrative unit records |
| `AdminUnit` | Union of the three, tagged on `level` |
| `Canton`, `Village` | BUCREP records |
| `PollingStation`, `CouncilElectoralSummary` | ELECAM records |
| `SourceInfo`, `DatasetMetadata` | Provenance: `sources` entries and `metadata` |

```ts
import { Schema } from "effect";
import { AdminUnit, Region, RegionPcode } from "cameroon-locations/effect";

declare const cached: string, payload: unknown;

Schema.decodeUnknownSync(Region)(JSON.parse(cached)); // a Region, or throws
Schema.is(RegionPcode)("CM002007"); // false

const unit = Schema.decodeUnknownSync(AdminUnit)(payload);
AdminUnit.match(unit, {
  region: (r) => r.name.en,
  division: (d) => d.regionPcode,
  arrondissement: (a) => a.divisionPcode,
});
```

## Cantons and villages

`/effect` only loads the administrative units, so it ships no decoder for
cantons, villages or polling stations: that data lives behind its own entry
point. Build one with `Schema.decodeTo` and the lookup of that entry point:

```ts
import { Effect, Schema, SchemaGetter, SchemaIssue } from "effect";
import { getCanton } from "cameroon-locations/cantons";
import { Canton, CantonId } from "cameroon-locations/effect";

export const CantonFromId = CantonId.pipe(
  Schema.decodeTo(Canton, {
    decode: SchemaGetter.transformEffect((id: string) => {
      const canton = getCanton(id);
      return canton
        ? Effect.succeed(canton)
        : Effect.fail(new SchemaIssue.InvalidValue({ message: `Unknown canton "${id}"` }, id));
    }),
    encode: SchemaGetter.transform((canton) => canton.id),
  }),
);

Schema.decodeUnknownSync(CantonFromId)("CM002007001-C01").label; // "Yaounde Ville"
```
