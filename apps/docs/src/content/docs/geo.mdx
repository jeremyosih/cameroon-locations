## locate

```ts
function locate(point: LngLat): Arrondissement | undefined;
```

The arrondissement containing a point, using the simplified OCHA polygons
bundled with the entry point. Points are `[lng, lat]`, like GeoJSON.

```ts
import { locate } from "cameroon-locations/geo";

locate([11.5167, 3.8667])?.name.fr; // "Yaoundé I"
locate([2.35, 48.85]); // undefined, that's Paris

// From the browser
navigator.geolocation.getCurrentPosition(({ coords }) => {
  const here = locate([coords.longitude, coords.latitude]);
});
```

It returns `undefined` outside Cameroon, and also within about 100 m of a
border, the simplification error, where the answer could be wrong. Fall back
to [`nearest`](#nearest) if you always need an answer.

### Locate a point

Click the map, type or paste coordinates, or use your own location. The
demo calls `locate`, walks up to the division and region with `getUnit`,
and falls back to `nearest` when the point is outside Cameroon or on a
border.

The same lookup in a script, for example to tag the rows of a CSV with
their arrondissement. Coordinates are usually written latitude first, so
swap them for `locate`:

```ts title="where-is.ts"
import { getUnit } from "cameroon-locations";
import { locate, nearest } from "cameroon-locations/geo";

function whereIs(lat: number, lng: number): string {
  const a = locate([lng, lat]);
  if (!a) {
    const near = nearest([lng, lat], { limit: 1 })[0];
    return near
      ? `outside Cameroon or on a border, nearest: ${near.unit.name.fr} (${near.distanceKm.toFixed(1)} km)`
      : "unknown";
  }
  const division = getUnit(a.divisionPcode);
  const region = getUnit(a.regionPcode);
  return `${a.name.fr} › ${division?.name.fr} › ${region?.name.en} (${a.pcode})`;
}

whereIs(3.8667, 11.5167); // "Yaoundé I › Mfoundi › Centre (CM002007001)"
whereIs(12.1348, 15.0444); // "outside Cameroon or on a border, nearest: Kousséri (9.8 km)"
```

`locate` needs no network or DOM, so it runs the same in Node, Bun, Deno,
workers and edge functions. The polygons are decoded once, on the first
call.

## nearest

```ts
function nearest(
  point: LngLat,
  options?: { level?: AdminLevel | undefined; limit?: number | undefined },
): readonly { unit: AdminUnit; distanceKm: number }[];
```

Units sorted by the distance from the point to their centroid. `level`
defaults to `"arrondissement"` and `limit` to 5; `Infinity` returns every
unit of the level, and a fractional limit is rounded down. Ties are ordered
by P-code. The array and its entries are frozen.

It never throws: a point with a `NaN` or infinite coordinate, a `limit`
below 1 (or `NaN`) and an unknown `level` all return an empty array.

```ts
import { nearest } from "cameroon-locations/geo";

nearest([9.7, 4.05]).map(({ unit }) => unit.name.fr);
// ["Douala I", "Douala II", "Douala IV", "Douala VI", "Douala III"]

nearest([9.7, 4.05], { level: "division", limit: 3 }).map(
  ({ unit, distanceKm }) => `${unit.name.fr} ${distanceKm.toFixed(0)} km`,
);
// ["Wouri 4 km", "Fako 51 km", "Sanaga-Maritime 55 km"]
```

## distanceKm

```ts
function distanceKm(a: LngLat, b: LngLat): number;
```

Great-circle (haversine) distance in kilometres.

```ts
import { getArrondissement } from "cameroon-locations";
import { distanceKm } from "cameroon-locations/geo";

const yde = getArrondissement("Yaoundé I");
const dla = getArrondissement("Douala I");
if (yde && dla) distanceKm(yde.centroid, dla.centroid); // 202.4
```

## Boundary files

Boundaries ship as GeoJSON `FeatureCollection`s (RFC 7946) simplified from
OCHA COD-AB, at three levels of detail, plus one TopoJSON file with all four
levels on shared arcs. Every level is dissolved from the same simplified
arrondissements, so borders nest and match exactly. Use `low` for overview
maps and small screens, the default up to about zoom 9, and `high` when
zoomed in to a city.

<GeoJsonFiles />

- Each feature's `id` is the OCHA P-code. `properties` are `pcode`, `level`,
  `name_fr`, `name_en`, `parentPcode`, plus `regionPcode` and `divisionPcode`
  where they apply.
- Each file has a top-level `metadata` member with the version, licence and
  sources, so the attribution travels with the data.
- The `.geo.json` / `.topo.json` extensions make Node, bundlers and
  TypeScript (`resolveJsonModule`) treat the files as JSON, with no loader.

```ts
// Node, Bun, Deno, Vite, webpack
import regions from "cameroon-locations/geojson/regions.geo.json" with { type: "json" };

regions.features.length; // 10
regions.features[0]?.properties.name_en; // "Adamawa"

// Or fetch it from a CDN
const url = "https://unpkg.com/cameroon-locations/geojson/regions.geo.json";
```

### Joining by P-code

The P-code is the join key between the boundaries and every record in the
package, so styling a map by your own data is a lookup:

```ts
import { getUnit } from "cameroon-locations";
import arrondissements from "cameroon-locations/geojson/arrondissements.geo.json" with { type: "json" };

const voters = new Map([["CM002007001", 117_438]]); // your data, keyed by P-code

const features = arrondissements.features.map((f) => ({
  ...f,
  properties: {
    ...f.properties,
    value: voters.get(f.properties.pcode) ?? 0,
    population: getUnit(f.properties.pcode)?.population2005?.total,
  },
}));
```

### Leaflet

```ts
import L from "leaflet";
import type { FeatureCollection, MultiPolygon, Polygon } from "geojson";
import { attribution } from "cameroon-locations";
import regions from "cameroon-locations/geojson/regions.geo.json" with { type: "json" };

const map = L.map("map").setView([7.37, 12.35], 6);

type Regions = FeatureCollection<Polygon | MultiPolygon, { name_fr: string }>;

L.geoJSON(regions as Regions, {
  style: { color: "#007a5e", weight: 1, fillOpacity: 0.08 },
  onEachFeature: (feature, layer) => layer.bindTooltip(feature?.properties.name_fr ?? ""),
}).addTo(map);

map.attributionControl.addAttribution(attribution());
```

### MapLibre

```ts
import type { FeatureCollection } from "geojson";
import { Map as MapLibreMap } from "maplibre-gl";
import { attribution } from "cameroon-locations";
import arrondissements from "cameroon-locations/geojson/arrondissements.geo.json" with { type: "json" };

const map = new MapLibreMap({
  container: "map",
  style: "https://demotiles.maplibre.org/style.json",
  center: [12.35, 7.37],
  zoom: 5,
});

map.on("load", () => {
  map.addSource("arrondissements", {
    type: "geojson",
    data: arrondissements as FeatureCollection,
    promoteId: "pcode",
    attribution: attribution(),
  });
  map.addLayer({
    id: "arrondissements",
    type: "line",
    source: "arrondissements",
    paint: { "line-color": "#007a5e", "line-width": 0.6 },
  });
});
```

### d3

d3-geo expects the opposite ring winding to RFC 7946 GeoJSON, so use the
TopoJSON file with `topojson-client`. TypeScript reads JSON string fields as
`string`, so the imported files need a cast to their GeoJSON or TopoJSON type,
as in these examples. Its objects are `country`, `regions`,
`divisions` and `arrondissements`.

```ts
import * as d3 from "d3";
import { feature, mesh } from "topojson-client";
import type { GeometryCollection, Topology } from "topojson-specification";
import data from "cameroon-locations/geojson/cameroon.topo.json" with { type: "json" };

type Objects = "country" | "regions" | "divisions" | "arrondissements";
const topology = data as unknown as Topology<Record<Objects, GeometryCollection>>;

const regions = feature(topology, topology.objects.regions);
const projection = d3.geoMercator().fitSize([640, 640], regions);
const path = d3.geoPath(projection);

const svg = d3.select("svg");
svg
  .selectAll("path")
  .data(regions.features)
  .join("path")
  .attr("d", path)
  .attr("fill", "#007a5e")
  .attr("fill-opacity", 0.08);
svg
  .append("path")
  .datum(mesh(topology, topology.objects.regions, (a, b) => a !== b))
  .attr("d", path)
  .attr("fill", "none")
  .attr("stroke", "currentColor");
```

For a ready-made React map, see the [Cameroon map](/docs/cameroon-map)
component.
