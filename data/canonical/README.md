# Canonical dataset

These files are generated by `tools/build-all.sh`; don't edit them by hand. Corrections go in `patches/` (text-extraction fixes) or `crosswalks/` (name→P-code decisions). Every entry there has a reason.

## Fields (ADM1–3)

- `pcode`, `parentPcode`, `level`
- `name.fr` and `name.en`: the OCHA COD-AB names. They are the primary names.
- `refName`: the OCHA ASCII reference name.
- `areaSqKm`, `centroid` `[lon, lat]`: from OCHA COD-AB.
- `aliases[]`: every spelling seen in any source, as `{ name, source, kind?, lang? }`. Spellings are never discarded.
- `population2005 { total, male, female, source, docPage?, textLine? }`
  - ADM3: the arrondissement total row in the BUCREP directory.
  - ADM1 and ADM2: BUCREP's department table on pp. 7–8.
- `hasc { code, source }`: ADM2 from the HASC table; ADM1 derived as the common prefix of its divisions.
- `elecam2025 { council, registeredVoters, pollingCentres, pollingStations }`: ADM3 only.
- `geoBoundariesShapeId`: ADM3 only. Linked by spatial overlap with the OCHA polygon, not by name.

Cantons and villages carry `population2005` plus `source { id, docPage, textLine, textLineEnd?, patched? }`. `docPage` is the page number printed in the BUCREP PDF.

## How each link was made

| Link | Method | Evidence |
|---|---|---|
| BUCREP text → records | Two independent extractions: `loc.txt` indentation and PDF typography (PyMuPDF). They agree on all 18,934 names and populations. 7 rows disagree on level and are listed in `patches/known-extraction-differences.json`; the build fails on any new disagreement. | `tools/compare-extractions.ts` |
| Record level (arrondissement, canton or village) | Indentation, checked against printed totals. 20 BELO rows patched, confirmed on PDF p. 298. | `patches/bucrep-loc-txt.json` |
| BUCREP → P-code | Exact normalised name within the matched parent, plus 15 manual decisions | `crosswalks/bucrep-codab.json` |
| ELECAM council → P-code | Same method, plus 39 manual decisions. Most of these are communes named after their chef-lieu, confirmed by OSM shape overlap and BUCREP village names. | `crosswalks/elecam-codab.json` |
| geoBoundaries ADM3 → P-code | Spatial: all 360 shapes fall 100% inside exactly one OCHA polygon | `tools/spatial-match-geoboundaries.ts` |

## Population reconciliation (2005)

- National total 17,463,836 = Σ regions (pp. 7–8 table).
- Σ arrondissement rows = 17,463,839. The +3 is all in Vallée-du-Ntem.
- Σ villages = 17,461,371. The gap comes from 29 canton or arrondissement totals printed inconsistently in the PDF. Both extractions agree on them, so the values are kept as printed and listed in `issues.json`.
